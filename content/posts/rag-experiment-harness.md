# How I A/B-test changes to this RAG — an eval-gated experiment harness

The chat you're talking to is a fully local retrieval-augmented-generation service. When I want to change one thing in its pipeline — swap the language model, swap the embedder, change how documents are chunked, add a reranker — I don't eyeball a few answers and call it. I run a locked experiment through a small reusable harness I built for exactly this kind of "should we swap X for Y?" decision.

## The discipline

The harness enforces a handful of rules that are easy to state and easy to violate:

- **AI-free measurement.** The only tokens an experiment spends are the answers-under-test themselves — questions times models. Everything else (discovering the pipeline's seams, scoring retrieval, computing the deltas, rendering the tables) is deterministic code that spends nothing. The harness prints the exact generation budget *before* it runs, so the cost is never a surprise.
- **One variable at a time, checked by the machine.** Every run is fingerprinted by its locked parameters — top-k, prompt template, temperature, context window — and by its eval set. A guard refuses to compare two runs that differ on more than the single axis under test, so a model-vs-model result can never be silently contaminated by, say, a different context window. The comparisons it's allowed to make are generated by that guard, not hand-picked afterward.
- **Build the ruler before you read it.** The eval set is frozen before any answer is looked at, and never reworded to chase a number — rewording a question changes what gets retrieved, which quietly moves the very thing you're trying to measure. A gap the eval exposes is a finding to record, not something to silently patch.
- **Either result is a win.** The harness doesn't care which way the answer comes out, and the rule is to report whatever the data shows — including the confounds.

## Its first real run

I pointed it at a concrete question: does this English-corpus RAG actually need Finnish support, and if it does, does a Finnish-built model beat the general ones? Three 8B local models on a Finnish eval set, everything else held identical, on a single GPU at zero cost.

The finding: the general models already synthesize acceptable Finnish from English source material, a Finnish-built model gives no measurable edge for this job, and the real lever turned out to be how the system handles off-scope requests — not the model. The full write-up lives in the Finnish-experiment post; the point here is the *method*. The next planned run varies two axes at once — a multilingual embedder alongside the English one, across the same three models — exactly the kind of matrix the single-variable guard exists to keep honest.

That's what the harness buys: it turns "I think Y is better than X" into a number I can defend, cheaply, without ever letting an AI grade its own homework.
