# ReadLog Laravel

ReadLog Laravel is the third version of Mikko Numminen's personal reading-log web application, and the second port: the original is Next.js and Prisma on Postgres, the first port is ASP.NET Core Razor Pages with EF Core, and this one is Laravel 13 on PHP 8.4. Each port treated the previous version as its specification. Users search for books across Open Library and Google Books, log what they finish with a format (book, audiobook or e-book), a finished-on date and a 0 to 5 star rating, then browse, search, edit and delete their library. A public "recently read" feed is open to everyone. One feature goes beyond the port: "ask your library", a natural-language search over the reader's own entries ("audiobooks I rated 5 last year", "the one about a desert planet") answered by a local Ollama, and degrading to the plain title search with a notice when Ollama is absent.

The source is at https://github.com/MikkoNumminen/readlog-laravel. There is no hosted instance: the app runs on the author's own machine from one Docker command and is put on a temporary public URL through a Cloudflare tunnel only when it needs to be shown. What the portfolio serves at https://mikkonumminen.dev/readlog-laravel is a static snapshot of the seeded demo, generated by the app's own `php artisan readlog:snapshot` command, on which search and forms are inactive and every page says so.

## Stack

| Concern | Choice |
|---|---|
| Runtime | PHP 8.4 |
| Framework | Laravel 13, Blade views, no JavaScript framework and no build step |
| ORM | Eloquent (Active Record), hand-written migrations |
| Database | SQLite by default; tested against a stock Postgres 16 in CI; the connection is entirely environment-driven |
| Auth | None in version 1, deliberately: a session-backed demo reader switcher stands in |
| Tests | Pest 4, 308 tests, run against both SQLite and Postgres |
| Static analysis | PHPStan via Larastan, level 6, in CI |
| Container | Docker Compose: nginx in front of php-fpm, SQLite in a named volume, Postgres as an opt-in override |
| Exposure | Cloudflare quick tunnel on demand (`scripts/tunnel-up.sh`), `readlog:smoke` to verify a running instance |
| AI search | Local Ollama: `nomic-embed-text` for embeddings, `qwen2.5:7b` to phrase answers; one embedding per entry in a plain JSON column, cosine in PHP; optional, degrades to title search |
| Operations | `ops/desktop/readlogctl.py`, a Windows desktop control panel: status board, on, off, tunnel on and off, smoke, embed, warm, ask |
| CI | GitHub Actions: formatting, PHPStan, the suite on SQLite, the suite on Postgres, the compose stack from a bare checkout, the snapshot generator end to end |

## What is notable

The migration was done as a learning-in-public exercise by a C# developer writing PHP and Laravel for the first time, and the process is the deliverable. `MIGRATION.md` maps every .NET building block to its Laravel counterpart with file references to both repositories, and then says what did not translate cleanly: Active Record versus data mapper (`$book->save()` is easy; what bites is that nothing checks the model against the schema), the absence of a date-only type (a 55-line custom cast replaces .NET's `DateOnly`), a cache that stores bytes rather than references (Laravel 13 refuses to unserialize classes from cache by default, and caching DTOs passed every test and failed in the browser), the absence of `await` (the two-provider fan-out uses `Http::pool`, which forced the provider clients to be split in two), and one Blade parsing rule with no Razor counterpart. `DECISIONS.md` logs every judgement call, just over a hundred of them, with one line of reasoning each.

The multi-source book search is ported faithfully, including two flaws the .NET version has: conflicting provider metadata is resolved by which record is richer, not which is right, and the de-duplication key strips everything outside ASCII, so two unrelated books with Cyrillic or CJK titles collapse into one. Both are pinned by tests that assert the current behaviour on purpose, so a future fix has to change a test knowingly.

`MIGRATION.md` also has a section on where the AI-assisted port produced wrong output and how each case was caught: nine cases from the first run; the self-reviews in STATUS.md carry the later ones, from a plausible-looking Eloquent `date` cast that writes a full datetime, to a memoisation that leaked one reader's session into another's request and was caught only because the test suite runs many requests in one process. The pattern is that failures cluster where the two ecosystems differ silently: same concept, same-looking API, different behaviour, no error at the point of the mistake.

"Ask your library" is built as three layers, each allowed to fail downward, the same posture as the author's feedback-intelligence project, deterministic first and the model only phrasing what was retrieved: exact filters (format, rating, year) parsed from the question by patterns and run as SQL, so the model is only ever shown entries that satisfy them; embeddings ranking the rest, the question and each entry embedded by `nomic-embed-text` with cosine similarity computed in PHP over the reader's rows; and a small chat model phrasing an answer over the top few as JSON with the ids it relied on, ids it was not shown being dropped, so it can only cite what it saw. What the model knows is what the log knows (title, author, format, rating, dates), so "the one about a desert planet" finds Dune because the model has heard of Dune, and "the science one about a man alone in space" is honestly answered with "none of these". Measured on the author's GPU, shared with two other models: the first question after a while took 47 seconds while the chat model loaded, later ones 0.5 to 4 seconds; a warm-up command runs at start-up for that reason. Timeouts, prompt wording and the parsing patterns are recorded in `DECISIONS.md` #94 to #103.

Cloud deployment was worked on and dropped as a deliberate decision, on cost. What was kept is everything that makes the app runnable anywhere: env-driven configuration, SQLite and Postgres both tested, a container that starts clean, a health route and a smoke check.
