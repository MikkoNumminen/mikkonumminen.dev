## Origin

ReadLog Laravel is the third build of Mikko Numminen's reading log and the second port: Next.js and Prisma first, ASP.NET Core Razor Pages second, Laravel 13 on PHP 8.4 third. It was done in a handful of runs with an AI coding agent driving and the author setting the brief, the review bar and the judgement calls, as a public exercise in which the migration process itself is the product. The .NET version was treated as the specification: where it does something odd, the odd thing was ported and written down, and two of those oddities are pinned by tests that assert the current behaviour on purpose. Version 1 scope was four things and nothing else: books, reading entries, the library search, and the multi-source Open Library plus Google Books lookup with its merge logic. Authentication was left out deliberately.

## Key technical choices and the why

- **Laravel 13, Blade, no JavaScript framework, no build step.** The brief asked for server-rendered views to keep the comparison with Razor Pages clean, and for an app that runs with `php artisan serve` after a clone. The stock Vite front end was removed in the second commit for that reason.
- **Eloquent, and a hand-written date cast.** PHP has no date-only type and Laravel's built-in `date` cast writes a full datetime, which broke the unique `(user, book, finished date)` index against the plain date an HTML input produces. `App\Casts\DateOnly` is 55 lines standing in for one C# type. A failing test found it; the docs would not have.
- **The public feed caches arrays, not objects.** Laravel 13 ships `serializable_classes: false`, so cached DTOs came back as `__PHP_Incomplete_Class`. It passed the whole test suite because tests use the array cache store, and returned a 500 on every second browser request. There is a test that forces a serialising store so it cannot happen again.
- **`Http::pool` for the two-provider fan-out.** PHP has no `await`; a pool needs every request handed over before any response exists, so both provider clients were split into `requestSearch()` and `parseSearch()`. That split is the visible cost of not having `await`, and cancellation has no counterpart at all.
- **No hosted instance.** A cloud deployment was worked on and dropped on cost. The app runs locally from one Docker command (nginx, php-fpm, SQLite in a volume, Postgres opt-in) and is exposed through a Cloudflare quick tunnel only for a demo. What the portfolio shows is a static snapshot generated by the app's own `readlog:snapshot` command.
- **PHPStan level 6 in CI**, added late, as the nearest thing to the `WarningsAsErrors=nullable` build the .NET version has.

## Dead ends and how they resolved

- **Memoising the current reader** to save three lookups per request leaked one reader's session into another's request, because the service holds a `Session` and a container binding outlives one request. Invisible under `php artisan serve`, where each request is a fresh process; caught immediately by the test suite, which runs many requests in one process. Reverted, reasoning left on the method.
- **The Google Books API key ended up in the log.** Guzzle puts the full request URL into a connection-failure message and Google only accepts the key in the query string. The .NET original does not have this problem, so there was nothing in the source to warn about it. Found by triggering a failure on purpose and reading the output.
- **The test suite silently went to the network** the moment provider search was wired into a page. Everything still passed; the only signal was the suite going from 2.8 seconds to 13. `Http::preventStrayRequests()` now makes it an error.
- **The first Postgres portability fix regressed SQLite** for Finnish titles: `mb_strtolower` in PHP is Unicode-aware, SQLite's `lower()` is ASCII-only. Both sides are now lower-cased by the same SQL function, and a title with an ä in it is the test.
- **The snapshot generator's second run wrote nothing.** Laravel reuses the command instance across `Artisan::call`s in one process, so run two inherited run one's page map. Its own test had passed because it only checked a stale file was gone.

## Where it stands

Feature-complete for version 1, then one feature beyond it: "ask your library", a natural-language search over the reader's entries through a local Ollama, built after the comparison was closed so the comparison stays honest, and built to degrade to the title search when Ollama is absent. Three PRs: the client and the embeddings, the search itself, the docs. It was the easiest feature in the codebase to write, because the port had already decided how an optional external service is treated (typed client, one exception, fake the transport and assert the fallback). And the small model got structured facts wrong with confidence (it listed a book rated 3 as unrated), which is exactly why the exact filters run as SQL in front of it and why the entries it saw but did not cite stay visible under its answer. 404 tests green on SQLite and on Postgres, PHPStan level 6, the portfolio address serving the live app when the machine is on and the snapshot when it is not, tunnel verified end to end by hand, and a desktop control panel for the whole thing. Authentication came later, as Google sign-in and nothing else, with reading kept public and a demo-writes switch so a visitor to the portfolio address can add to the showcase library; hosting stays a question mark with the options listed and none recommended.
