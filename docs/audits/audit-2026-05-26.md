## Findings by area

### Resource lifecycle

- [src/lib/transitions/pageTransition.ts:289](src/lib/transitions/pageTransition.ts#L289) [high] — `TransitionRunner` registers `window.addEventListener('resize', this.onResize)` directly (not via the `AbortController.signal` used by `initPageTransitions`); the orchestrator only calls `controller.abort()` and `runner.cancel()`, never `runner.dispose()`, so the resize listener leaks on every HMR/re-evaluation and accumulates across hot-reloads in dev.
- [src/lib/three/homeScene.ts:231](src/lib/three/homeScene.ts#L231) [low] — `collisionFlashLight` is added to the scene at line 231 but is missing from the `scene.remove(...)` argument list in `dispose()` (lines 937-948); the corresponding `collisionFlashLight.dispose()` is called, but the light remains parented to the scene at teardown. Cosmetic — the scene itself is being torn down — but inconsistent with the surrounding handling.
- [src/lib/three/projects/buildExternalIndicator.ts:19-20](src/lib/three/projects/buildExternalIndicator.ts#L19) [medium] — `sharedPulseTexture` / `sharedPulseTextureRefCount` are module-level mutable singletons. The increment in `buildExternalIndicator` (line 89) and the decrement in `disposeExternalIndicators` (line 160) are balanced for the current call sites, but the design assumes one-shot lifecycle. If a second `createProjectsScene` mounts before the first finishes disposing (selectByID / hot-reload), the refcount becomes incorrect and the texture can be disposed mid-use.
- [src/lib/three/buildMeteors.ts:292](src/lib/three/buildMeteors.ts#L292) [low] — `dispose()` disposes each meteor's geometry + material but does not detach lines from `group`. Cleared by `scene.clear()` in the caller's dispose, but inconsistent with sibling builders.
- [src/lib/three/buildLetterFlashes.ts:159-165](src/lib/three/buildLetterFlashes.ts#L159) [low] — `dispose()` detaches each `PointLight` from its parent but never explicitly disposes the materials/textures; `PointLight.dispose()` is a no-op without a shadow map so this is fine *today*, but the comment ("PointLight.dispose() is a no-op without a shadow map") locks future maintainers into that invariant — adding a shadow map would silently leak.
- [src/components/contact/MobileContactCard.astro:277-278](src/components/contact/MobileContactCard.astro#L277) [low] — Mobile-card teardown listens for `beforeunload` and `pagehide` for cleanup. On bfcache restore, `pagehide` fires but the script body has already run (and `cancelled` is now true), so the auto-playing terminal cannot be re-driven. Not a leak — but a "restore from back-forward cache shows a half-finished terminal" UX bug.

### Data integrity

- [src/lib/terminal/skills.ts:72](src/lib/terminal/skills.ts#L72) [medium] — `fetch(REGISTRY_PATH, …).then(r => r.json())` casts the response to `SkillRegistry` with no runtime validation. A future malformed registry (renamed field, wrong type) would produce silent corruption inside `renderAggregate`'s `s.receipt?.annual_total ?? 0` sum.
- [src/page-content/HomePage.astro:34](src/page-content/HomePage.astro#L34) [low] — `s.split(':')[0]!.trim()` — non-null assertion on the result of `split(':')[0]`. `split` always returns at least one element, so the assertion is safe in practice — but it pre-empts `noUncheckedIndexedAccess`, making the failure mode invisible if `s` is ever empty (e.g. if upstream filtering changes).
- [src/lib/gsap/experienceTimeline.ts:140-146](src/lib/gsap/experienceTimeline.ts#L140) [low] — `parseHex` slices a string without validating length; a malformed input (`#abc`, `#abcd`) silently produces NaN channels which then propagate as `NaN` into the interpolated color string. Inputs come from the PHASES literal so this is data-bound today, but no guard if a future maintainer adds a non-`#rrggbb` colour.
- [src/lib/terminal/skills.ts:91-94](src/lib/terminal/skills.ts#L91) [low] — `formatNumber` collapses `Infinity` / `NaN` (untyped path from `s.receipt.annual_total`) to the literal string `"Infinity"` / `"NaN"`. Not a crash, but a degenerate display if the registry ships a bad value.
- [src/lib/three/buildExperienceZoneDecor.ts:401](src/lib/three/buildExperienceZoneDecor.ts#L401) [low] — `respawnMeteor` uses `sign > 0 ? angle : Math.PI - angle` for rotation. The mirror is conceptually correct for the leftward case but no tests guard the relationship between `sign` and `m.material.rotation` against drift if either is reformulated.

### Concurrency

- [src/lib/transitions/pageTransition.ts:681-683](src/lib/transitions/pageTransition.ts#L681) [medium] — `globalThis.__pageTransitionAbortController` is a single shared mutable; if two `initPageTransitions()` calls overlap (unlikely on a static site, but possible during HMR), the second `.abort()` happens before the second controller is stored, leaving the first controller still active and double-firing aborts on listeners.
- [src/components/BackgroundAudio.astro:556-565](src/components/BackgroundAudio.astro#L556) [low] — `onScroll` uses a `ticking` flag rAF-throttle, but does *not* observe the `crossfading` flag at the time the rAF callback runs — it only checks `!crossfading` inside the rAF. A crossfade that starts between the scroll-event and the rAF callback is fine, but the inverse (a crossfade that ends mid-callback) could still set `active.volume` against the now-old "active" deck if `getActive()` flipped right between the check and the assignment. Window is one event-loop tick.
- [src/components/home/HeroVoiceover.astro:140-141, 154-155](src/components/home/HeroVoiceover.astro#L140) [medium] — The pattern `await voice.play(); if (!wantOn) voice.pause()` solves the "play() interrupted by pause()" rejection, but there is still a window between `voice.currentTime = 0` (line 138) and the awaited `voice.play()` where a user toggle could flip `wantOn` to false; the next `playResume()` invocation will then seek to currentTime=0 rather than the user's mid-clip position because the seek already mutated state. Effect: occasional restart-from-zero on rapid double-toggles.
- [src/lib/projects/drawer.ts:204-222](src/lib/projects/drawer.ts#L204) [medium] — `close()` reads `lastFocused`, attempts to focus it, then nulls the field. If `close()` runs re-entrantly (escape key during a click-outside) the second invocation observes `lastFocused === null` and falls through to focusing `document.body`. No locking — but the visible symptom is a focus jump rather than data corruption.
- [src/lib/three/projectsScene.ts:455-468](src/lib/three/projectsScene.ts#L455) [medium] — `planetAngles.get(entry)!` uses non-null assertion inside the per-frame tick. The Map is seeded at construction (lines 199-201) and never deleted, so the lookup is safe today. But if a future change ever clears the Map (selection state reset, etc.) the `!` becomes a runtime `undefined` propagated through the orbit math, producing NaN positions.

### Error paths

- [src/lib/three/projects/buildExternalIndicator.ts:160-167](src/lib/three/projects/buildExternalIndicator.ts#L160) [medium] — `disposeExternalIndicators` decrements the shared refcount in the loop *before* checking `<= 0`. If an indicator iteration throws (e.g. a `dispose()` on an externally-replaced material), the loop exits with a decremented refcount that no longer matches the surviving indicators, and the shared texture may be disposed prematurely on the next call.
- [src/lib/terminal/commands.ts:152-156](src/lib/terminal/commands.ts#L152) [low] — `fetch(target.url, { method: 'HEAD' })` has no timeout / `signal`. On a hung network the user sits at "preparing your download…" with no recourse (and the `available = false` branch never runs). Add `AbortSignal.timeout(5000)` or similar.
- [src/lib/terminal/skills.ts:72, 224](src/lib/terminal/skills.ts#L72) [low] — Same pattern — both `fetchRegistry` and the `--json` HEAD probe lack timeouts. Less critical than the download path because the file is local, but a stale fetch promise lives in the module-level `registryCache` for `CACHE_TTL_MS` (60 s) and prevents recovery.
- [src/lib/transitions/pageTransition.ts:732-737](src/lib/transitions/pageTransition.ts#L732) [high] — The promise chain `phaseA → phaseB → window.location.href = href` has no `.catch()`. If either phase rejects (rAF aborted by a tab-switch mid-animation, canvas context loss), the navigation never fires and the user is stuck on the source page with the overlay locked in `animating` state — only `pageshow` (back/forward) recovers.
- [src/lib/three/homeScene.ts:357-359](src/lib/three/homeScene.ts#L357) [high] — `if (!mikkoLine || !nummLine) throw new Error(...)` — a thrown error inside `createHomeScene` (an async function) propagates to the awaiting `HomePage.astro` script's outer `try/catch`, which logs and continues, **but the partially-allocated resources up to that point** (renderer, scene, environment maps, lights, font) are *not* disposed. WebGL context + textures stay allocated until the page reloads.
- [src/page-content/HomePage.astro:141-143](src/page-content/HomePage.astro#L141) [medium] — `catch (err) { console.warn('home scene failed to init', err); }` — when init throws mid-way through `createHomeScene`, the caller has no `sceneHandle` and therefore cannot call dispose on the half-built scene. Same leak vector as the homeScene line 358 throw above; counted separately because the fix lives at the call-site.

### External boundaries

- [src/components/BackgroundAudio.astro:574-575](src/components/BackgroundAudio.astro#L574) [low] — `sessionStorage.setItem(POS_KEY, String(active.currentTime))` uses `beforeunload`. Modern browsers (Safari, mobile Chrome) are increasingly hostile to `beforeunload` for bfcache eligibility, and may not fire it on mobile tab-kill. Acceptable for the "music resumes mid-track" feature where worst case is restart-from-zero, but the same pattern is repeated in `HomePage.astro` / `ProjectsPage.astro` / `ExperiencePage.astro` for *scene disposal* — a missed `beforeunload` there leaks the entire WebGL renderer until GC.
- [src/lib/terminal/terminal.ts:81-91](src/lib/terminal/terminal.ts#L81) [medium] — The clipboard write-then-restore pattern (lines 81-90) catches the write failure but does NOT check that `target` (the copy button) is still in the DOM after the 1400 ms timeout. If the user clears the terminal (Ctrl-L → `ctx.clear()` → `output.innerHTML = ''`) between the click and the timer, the restored `target.textContent = original` write fires on a detached node. Not a crash — but the button reference is held in the closure for the full 1.4 s, defeating GC and pinning whatever subtree it was part of.
